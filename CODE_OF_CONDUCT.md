# Code of Conduct

## Our standard

Root.ark should remain a productive technical space. Contributors and maintainers are expected to communicate respectfully, focus criticism on the work, and make room for evidence-based disagreement.

Expected behavior includes constructive technical feedback, good-faith questions, correction of mistakes, and respect for privacy and security boundaries.

Unacceptable behavior includes harassment, threats, discriminatory abuse, doxxing, publishing private data or credentials, deliberate disruption, and knowingly misleading security or validation claims.

## Scope

This policy applies to issues, pull requests, reviews, project discussions, and other public Root.ark project spaces.

## Enforcement

Maintainers may edit, hide, lock, or remove content; reject contributions; or restrict participation when necessary to protect contributors and the project.

Security vulnerabilities must follow [SECURITY.md](SECURITY.md) instead of public conduct-reporting channels.

For sensitive conduct concerns, contact the repository owner privately through GitHub.
