## Scope and governing rule

This document is the canonical local reconciliation of Issue #6. The Issue #6 candidate list is not a commitment or implementation authorization. A candidate may proceed only after its prerequisites and owner decisions are complete, a separate future issue defines one coherent scope, and that issue receives explicit approval. This Phase 11 task changes documentation only; it does not implement Phase 12, 13, or 14 work.

The current repository, `docs/plan-tree.md`, `docs/issue-ledger.md`, `docs/security/phase-10-totp.md`, and the accepted Phase 10 evidence are the evidence sources. Existing code or historical validation is not treated as proof of a complete future feature. `implemented` means accepted within an already scoped phase, `partial` means a related current surface exists while the candidate remains incomplete, `future` means no approved implementation exists, and `owner-decision` means sequencing is blocked by product choice.
