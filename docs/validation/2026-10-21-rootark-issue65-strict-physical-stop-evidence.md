## Scope implemented

The opt-in PostgreSQL `head.require_stop_proof` policy is operator-provisioned per keyring and immutable by the runtime role. Existing reference scopes default to `false` for compatibility; a strict scope requires a host-key ID, random process epoch and OS PID on admission. The authoritative head and admission triggers reject non-monotonic generation/phase changes, forged state transitions and strict `FINISHED` without a durable independent STOP row. A stopped admission is still bound to its original scope/worker/generation. The gate-only SQL login cannot INSERT STOP rows or silently mark pending without them.

`Zk1IsolatedProcessStopSupervisor` owns the direct child-process handle, deliberately starts a fixture worker without inherited secrets and signs a versioned deterministic-CBOR Ed25519 STOP proof only after **both** OS `exit` and `close` have been observed. The proof binds exact scope, admission, principal, generation, host-key ID, process epoch, PID, observation time and STOP outcome; concurrent/lost-ACK retries return the same signed bytes. An independently provisioned `zk1_stop_runtime` role may record the verified proof without access to the gate transition or ciphertext-write privileges, and cannot mutate the head even though it has nominal row-lock permission. A trusted operator must provision and isolate its distinct login and host signing key.

## Independent adversarial finding and correction

Independent review reproduced a **conditional P2**: PostgreSQL 18.6 itself checked only `sha256(signed_proof) = proof_digest` plus SQL admission identity. With the *separate STOP SQL credential* (not the gate credential), the reviewer inserted 160 random bytes and their hash as a STOP row **without any kernel-observed process exit or valid Ed25519 signature**. An uncompromised gate Node method then accepted `FINISHED`. A new disposable-PostgreSQL regression reproduced this behavior (**RED**).

The trusted `Zk1SharedPgGateAuthority` now has an **explicit independently pinned host STOP public key**. For a strict scope, `finishIoAdmission` revalidates the stored Ed25519 proof against the exact admission scope, PID, epoch, host ID, principal and generation before accepting it. `markPending` checks all strict admissions' signed proofs again, including on PENDING retries after a restart. Historical persisted proofs are verified against their signed original observation time, rather than expiring a valid durable fact after delayed ACK; proof freshness is separately checked by the independently trusted STOP recorder *when inserted*. An unconfigured strict gate fails closed; its isolated runtime factory accepts opt-in `stopPinned` key configuration.

In the regression, the independently scoped STOP SQL login can still INSERT a fabricated row, but the normal GateAuthority rejects it, leaves admission `STOP_REQUESTED` and does not issue `FINISHED`. Even if the gate SQL credential is also independently compromised and the attacker updates admission to `FINISHED` outside Node, the honest GateAuthority still rejects `markPending` and leaves the head `QUIESCING`. These tests passed **GREEN** against the disposable real PostgreSQL service.

## Remaining security limitations — do not promote to production

The **database itself cannot validate Ed25519** with the supported built-in SQL primitives. Simultaneous possession of the gate **and** STOP SQL credentials can still bypass the Node verifier with raw `UPDATE` statements; independently trusted credentials, operating-system process isolation and the pinned verifier are all required. Compromised supervisor signing key or operating system can lie about an exit. The supervisor watches only one direct child process — **not descendants, subprocess escape, external cloud writes, local storage workers, network/socket buffers or remote host/provider STOP attestations**. The disposable child deliberately has no file, cloud or network data-plane effects. The physical PostgreSQL ciphertext write fence is the independently proven real effect point, not the child STOP test fixture. This milestone does not constitute proof that all Root.ark storage/egress workers have been stopped.

The reference PostgreSQL authority has a single primary, not an independently operated multi-host consensus cluster. GET/egress remains intentionally unavailable after earlier physical leak reproduction. No production S3/Drive provider is fenced per chunk; source-provider inventory/preflight is only read-only and cannot be called a reversible migration. Normal client upload/download, device-authenticated ZK commitment and normative CAS/witness terminal reopening/recovery remain unfinished. No real user data, production database, deploy, push, merge, or issue closure was performed.
