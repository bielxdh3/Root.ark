## Restore transaction model and residual boundary

1. The archive, manifest, checksum, path set, and quarantine payloads are validated before mutation. Full local pre-images are staged and verified under the durable restore coordinator.
2. Active requests and cooperating workers are quiesced. Current backup authorization is revalidated after quiescence, before the pre-restore backup, and immediately before local commit.
3. The local apply phase replaces only selected quarantine state, JSON metadata, uploads, and SQLite database/sidecars. The coordinator records progress. If the local phase errors, the durable coordinator remains and immediate compensation is not performed; the next startup retries reverse-order compensation from verified pre-images before admitting requests. If that startup retry also fails because of storage errors, permissions, unavailable filesystems, or external writers, startup remains blocked and manual recovery may be necessary.
4. Before any restore mutation, cancellation is persisted before temporary/pre-image cleanup. Startup treats a cancelled coordinator as cleanup-only. If cleanup cannot complete, the service remains behind the startup barrier; the valid pre-restore backup is retained where needed.
5. After local commit, startup applies required migrations/recovery before admitting requests. Cloud provider reconciliation is a separate durable, retryable queue; identity or provider failure keeps the affected startup/access path blocked until reconciliation resumes.

This is recoverable local coordination, not a globally atomic visibility switch across quarantine, filesystem, JSON/SQLite, and remote cloud APIs. External writers that bypass the application barrier can race the restore. Cloud APIs cannot participate in the local filesystem/database transaction, so their effects are reconciled idempotently after the local commit rather than rolled back atomically. Node.js does not provide portable Windows directory-entry fsync; sudden-power-loss durability is weaker there. Provider interoperability, hostile local writers, and deployed multi-hop proxy topology were not validated by this snapshot.
