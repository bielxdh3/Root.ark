## Restore semantics and remaining boundaries

Restore validates the archive, manifest, checksums, and paths before mutation, then stages verified local pre-images under a durable coordinator and quiesces cooperating requests/workers. Authorization is revalidated before commit. The local apply covers quarantine, JSON metadata, uploads, and SQLite state. On local failure the durable coordinator remains; startup retries reverse-order compensation before admitting requests. If recovery fails again, startup stays blocked and manual recovery may be needed. After local commit, migrations/recovery run before admission and cloud providers reconcile through a durable idempotent queue; provider failure does not silently roll back or corrupt local authoritative state, but can leave remote state pending and the relevant access/startup path blocked.

This is recoverable local coordination, not whole-restore global atomicity. External writers that bypass application barriers remain outside the guarantee. Cloud APIs cannot join a portable local filesystem/SQLite transaction. Portable Windows directory-entry `fsync` is unavailable. Live provider interoperability and production deployment topology remain unverified.
